# Список изменений

Все релизы We1ssBoard, новые сверху. Окно **Обновить** в панели показывает
записи между вашей версией и новой, а у каждого релиза на GitHub есть своя
запись. Английская версия: [CHANGELOG.md](CHANGELOG.md).

Разделы: **Добавлено** (новые возможности), **Изменено** (то, что теперь
работает иначе), **Исправлено** (ошибки), **Удалено**, **Несовместимые
изменения** (нужны действия с вашей стороны или ломается старая настройка),
**Известные проблемы** (что нашлось после выхода и в какой версии исправлено).

## [1.9.0] - 2026-10-23

### Несовместимые изменения
- Дочернюю панель с самоподписанным сертификатом можно подключить только приглашением,
  созданным на версии 1.9.0 или новее (в нём должен быть отпечаток сертификата).
  Обновите дочернюю панель или поставьте ей публично доверенный сертификат.

### Добавлено
- Окно **Обновить** показывает список изменений между установленной и новой
  версией, на русском или английском в зависимости от языка панели.
- Вкладки по узлам на страницах «Клиенты» и «Подключения» → «Инбаунды»:
  **Локальная панель** и по вкладке на каждый подключённый узел (с точкой
  «в сети»). У каждой вкладки свой список, свои счётчики и свой итог трафика,
  поэтому строки и трафик узла больше не смешиваются с локальными. Открытая
  вкладка сохраняется в адресе (`?node=`).
- Параметр `node=local|<id>` у `GET /panel/api/clients/list/paged`: ограничивает
  страницу, общее число и сводку одной вкладкой.
- Кнопка **Выбрать всех (N)** в Telegram WEB Proxy → «Добавить в подписки». Она
  пропускает клиентов, у которых уже есть веб-прокси, и клиентов, которые есть
  только на инбаундах подключённых узлов.
- `GET /panel/api/server/getChangelog` отдаёт разобранный список изменений для
  окна обновления.
- Описание каждого релиза на GitHub теперь содержит его запись из CHANGELOG на
  английском и русском.
- README: установка и настройка Telegram WEB Proxy, в том числе релей на узле и
  управление им из главной панели.

### Изменено
- Панель собирается на Go 1.27.3: он не доверяет скомпрометированным
  промежуточным сертификатам в `crypto/x509` (GO-2026-6809), а проверка
  REALITY-цели проверяет сертификаты через него.
- Встроенный Xray-core 26.10.21. XTLS отозвали 26.10.10 и 26.10.17: они доверяли
  скомпрометированным промежуточным сертификатам; 26.10.21 их исключает и собран на
  Go 1.27.3. Сборка релизов падала, потому что архив 26.10.10 удалён.
- Таблицы клиентов и инбаундов помещаются в свою карточку: ширина столбцов
  подогнана под содержимое, а если окно слишком узкое, наименее важные столбцы
  скрываются в заданном порядке. В меню **Столбцы** такой столбец показан
  снятым и заблокированным с подсказкой «не хватает места», пока окно снова не
  станет достаточно широким.
- Скорость в таблицах показывается в две строки (отдача и загрузка), поэтому
  столбец «Скорость» занимает 128 px вместо 216.
- Структура репозитория: Docker-скрипты перенесены в `docker/`, systemd-юниты и
  скрипт OpenRC — в `packaging/`, документы для разработчиков — в `.github/`.
  `install.sh` и `update.sh` по-прежнему находят юниты старых тегов по старым
  путям.

### Удалено
- Фильтр **Узлы** в фильтрах клиентов и выпадающий список узлов на странице
  инбаундов: их заменили вкладки по узлам.

### Исправлено
- Подключение узла по приглашению больше не доверяет любому TLS-сертификату. Узел
  отвечает админским API-токеном, и кто угодно на пути мог перехватить одноразовый код
  и токен. Теперь приглашение панели на https содержит SHA-256 её сертификата; главная
  панель отправляет код, только если сертификат публично доверенный или совпадает с
  этим отпечатком, а узел с самоподписанным сертификатом сохраняет в режиме TLS `pin`.
  Адрес в приглашении должен быть обычным URL http(s) (CodeQL #10, #11).
- Проверка версии в workflow релиза работает с токеном только на чтение (CodeQL #14).
- В окне уже примерно 1600 px таблицы клиентов и инбаундов вылезали за карточку и
  обрезали последние столбцы («Скорость», «Срок») по краю.
- Страница API Docs включала DOMPurify 3.4.16 с тремя критичными уязвимостями
  (GHSA-cg2g-xh64-v4q7, GHSA-mrv2-3pqr-j5jr, GHSA-c6gr-qvv4-5v3f); теперь 3.4.17.

## [1.8.4] - 2026-10-20

### Добавлено
- `install.sh` и `update.sh` пишут `/etc/sysctl.d/99-quic.conf`: буферы
  UDP-сокетов (`rmem/wmem_default` 4 МиБ, `max` 16 МиБ) и BBR, если ядро его
  поддерживает, после чего перезапускают панель, чтобы Xray открыл сокеты с
  новыми буферами. Раньше Hysteria с обфускацией salamander получала буфер
  208 КиБ, теряла пакеты и большую часть скорости. Отключение:
  `XUI_QUIC_TUNING=false`. Если файл уже есть после ручного исправления, он
  приводится к тому же виду; неизменившийся файл не вызывает перезапуска.

### Исправлено
- `migrate-3xui.sh` завершался, когда 3x-ui уже был остановлен и отключён, если
  We1ssBoard не стартовал: автоматический откат не запускался, и сервер
  оставался без прокси. Теперь скрипт ждёт службу, печатает последние строки
  лога панели и возвращает 3x-ui.
- Импорт из 3x-ui прерывался с «auth is not any value 3x-ui had», если пароль
  или auth клиента в таблице клиентов 3x-ui отличался от копии в JSON
  инбаунда. Значение из таблицы (то, которым 3x-ui реально пользуется)
  сохраняется, а предупреждение называет поле.

### Добавлено

## [1.7.0] - 2026-10-19

### Несовместимые изменения
- Панель переименована из FullBoard в **We1ssBoard**: путь Go-модуля, бинарник,
  CLI (`we1ssboard`), юниты systemd/OpenRC, пути по умолчанию (`/usr/local`,
  `/etc`, `/var/log`), файлы релизов и Docker-образ. `update.sh` один раз
  переносит существующую установку FullBoard и оставляет симлинки на старых
  местах, поэтому сохранённые пути к сертификатам и команда `fullboard`
  продолжают работать. Теги до 1.7.0 новыми скриптами не ставятся.
  `install.sh` не ставит панель рядом с FullBoard и предлагает
  `fullboard update`.

### Добавлено
- Мобильное приложение (Expo) для Android: обзор с перезапуском Xray и панели,
  клиенты, инбаунды, узлы, профили Telegram WEB Proxy.
- Telegram-бот: `/nodes` и `/webproxy` для админов (состояние узла, задержка,
  CPU/RAM, версия Xray, последняя ошибка; хост релея, профили, привязанные
  клиенты, последняя ошибка синхронизации).
- Telegram WEB Proxy на узле: добавление, правка и удаление его профилей из
  вкладки узла и добавление профиля в подписки сразу многим клиентам
  (`POST /panel/api/tgWebProxy/bindings/bindMany`).
- Пресеты оформления Ocean (синий) и Emerald (зелёный).
- Новый логотип и надпись.

### Исправлено
- Проверка «профиль привязан» считала привязки всех релеев по имени: клиент
  на «default» узла мешал удалить «default» мастера, а используемый профиль
  узла удалялся. Теперь проверка идёт отдельно по каждому релею.

### Известные проблемы
- Однажды прерванное обновление оставляло установку разделённой между старыми
  и новыми папками. Исправлено в 1.7.1.

## [1.6.1] - 2026-10-18

### Исправлено
- `fullboard legacy` отклонял все версии 1.x (нижняя граница v2.3.5 от 3x-ui)
  и заново запускал первичную настройку. Теперь он обновляет панель на месте до
  выбранной версии.
- Тег на коммите без поднятой версии давал релиз только с Windows-сборкой,
  помеченный как Latest, и это ломало установку и самообновление у всех.
  Теперь релиз создаётся, только когда собраны все платформы.
- Импорт из 3x-ui: клиент на двух протоколах не проходил проверку («id changed
  from to …»), а работающий 3x-ui мог сорвать тестовый импорт. Теперь каждое
  объединённое поле сверяется со всеми записями этого email, прочитанными из
  снимка.
- `migrate-3xui.sh` ждёт подтверждения, если тестовый импорт выдал
  предупреждения (`--yes` оставляет запуск без вопросов).

## [1.5.0] - 2026-10-18

### Добавлено
- Синхронизация с 3x-ui v3.10.2: Xray-core 26.10.10, XDRIVE, MASQUE,
  обфускация Gecko для Hysteria2 в Clash, шифрование VLESS по умолчанию,
  отчёты о падениях, запасной userspace TUN, scope node-admin у API-токенов.

### Исправлено
- С Xray 26.9.9 перескок портов Hysteria молча перестал работать в аутбаундах
  и JSON-подписках: панель писала мёртвый ключ `quicParams.udpHop` вместо маски
  `udphop`, и весь трафик шёл одним UDP-потоком. Миграция базы переписывает
  старые настройки.
- Токены admin и node-admin сохраняют свой scope поверх mTLS, поэтому
  удалённая панель узла работает; сертификат без токена даёт только
  node-sync.

### Изменено
- Встроенный Xray-core 26.10.10 (26.9.30 не понимает новые настройки udphop,
  xdns и MASQUE).

## [1.4.3] - 2026-10-17

### Добавлено
- Панель сама запускает официальные MTProxy-бэкенды для каждого профиля
  веб-прокси (до 16 секретов на порт, порты закрыты снаружи). Второй профиль
  больше не указывает на порт, который никто не слушает, и выделенные секреты
  работают (mtg принимал только FakeTLS: «incorrect first byte of secret»).
- Выделенный секрет отключённого клиента «паркуется», а не обслуживается.

### Исправлено
- Вставка приглашения узла всегда падала с «request body failed validation».
- Проверка Caddy шла без переменных окружения caddy.service, и любое

  появляется WebSocket-профиль.
- Релей, установленный позже из панели, не мог писать в `/etc/tproxy-server`
  (read-only file system): установка и обновление создают папку заранее.
