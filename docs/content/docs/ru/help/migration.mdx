## С 3x-ui

We1ssBoard читает базу 3x-ui напрямую и переносит инбаунды, клиентов, их трафик
и историю IP, настройки панели и учётную запись администратора. Каждая строка
сверяется с исходной базой, и импорт не завершится, если что-то потерялось. Базу
3x-ui он открывает только на чтение и не меняет.

Скрипт миграции делает весь переход на том же сервере и умеет его отменить.
Нужны root, systemd и SQLite в обеих панелях (у 3x-ui это вариант по умолчанию).

<Steps>

<Step>
### Установите We1ssBoard

Поставьте его рядом с 3x-ui (см. [Установка](/ru/docs/guide/installation)).
Останавливать 3x-ui не нужно: по умолчанию установщик выбирает случайный порт
панели, и панели не мешают друг другу. Не задавайте ему порт 3x-ui.
</Step>

<Step>
### Запустите скрипт миграции

```bash
bash <(curl -Ls https://raw.githubusercontent.com/WeIbSchatten/We1ssBoard/main/migrate-3xui.sh) migrate
```

Скрипт:

1. делает **пробный импорт**, пока 3x-ui продолжает обслуживать клиентов; если
   он не удался, ничего не останавливается и не меняется. Если импорт вывел
   `WARNING`, скрипт спросит, продолжать ли;
2. останавливает обе панели и сохраняет 3x-ui (базу, `/usr/local/x-ui`,
   юнит службы, команду `x-ui` и её env-файл) и текущую базу We1ssBoard в
   `/root/3x-ui-migration-<дата>/`;
3. импортирует `x-ui.db`, отключает `x-ui.service` и запускает We1ssBoard;
4. если We1ssBoard не удержался в работе, сам возвращает 3x-ui и показывает
   последние строки журнала We1ssBoard.

Флаг `--yes` отключает вопросы, например для автоматизации.
</Step>

<Step>
### Войдите

Откройте панель по адресу **3x-ui** и войдите с логином и паролем **от 3x-ui**:
порт, путь и учётная запись перенеслись вместе с настройками. Ссылки клиентов и
адреса подписок не меняются, поэтому клиентам ничего перенастраивать не нужно.
</Step>

</Steps>

Строка `WARNING` в выводе импорта означает, что значение стоит проверить:
например, у клиента в разных инбаундах были разные лимиты или файла сертификата
нет на этом сервере. Полный вывод сохраняется в `import.log` в папке бэкапа.

### Откат на 3x-ui

```bash
bash <(curl -Ls https://raw.githubusercontent.com/WeIbSchatten/We1ssBoard/main/migrate-3xui.sh) rollback
```

Команда восстанавливает 3x-ui из последнего бэкапа точно в прежнем виде, вместе
с тем, была ли её служба включена и запущена, и сверяет восстановленный `x-ui.db`
с контрольной суммой. Импортированная база We1ssBoard остаётся в папке бэкапа.
Чтобы взять более старый бэкап, укажите его папку после `rollback`; `status`
показывает все бэкапы. Без аргументов скрипт открывает меню с теми же действиями.

<Callout>
  Ограничение по IP работает только с fail2ban. Если fail2ban не запущен, импорт
  обнулит такие лимиты, как это сделало бы обновление 3x-ui, и сообщит об этом.
</Callout>

### Импорт вручную

Без скрипта (например, если нет systemd) тот же импорт можно выполнить руками.
Остановите обе панели, чтобы никто не писал в базы, уберите пустую базу
We1ssBoard (импорт создаёт базу сам и не перезаписывает существующую),
импортируйте и переключите службы:

```bash
systemctl stop x-ui we1ssboard
mv /etc/we1ssboard/we1ssboard.db /etc/we1ssboard/we1ssboard.db.empty
/usr/local/we1ssboard/we1ssboard import-3xui -src /etc/x-ui/x-ui.db
systemctl disable --now x-ui
systemctl start we1ssboard
```

С `-dst` результат пишется в другой файл вместо рабочей базы — так удобно
сделать пробный прогон.

## С FullBoard

В версии 1.7.0 FullBoard переименован в We1ssBoard. Обновитесь как обычно (из
панели или командой `we1ssboard update`): обновление само перенесёт всё на новые
имена и оставит ссылки для совместимости. Вручную ничего делать не нужно.

| FullBoard | We1ssBoard |
| --- | --- |
| `/usr/local/fullboard` | `/usr/local/we1ssboard` |
| `/etc/fullboard/fullboard.db` | `/etc/we1ssboard/we1ssboard.db` |
| `fullboard.service` | `we1ssboard.service` |
| команда `fullboard` | команда `we1ssboard` |
| юниты `fullboard-mtproxy-*` | юниты `we1ssboard-mtproxy-*` |

Если обновление когда-то прервалось, файлы могут оказаться и в `/etc/fullboard`,
и в `/etc/we1ssboard`. Обновление до 1.7.1 и новее объединяет их. До этого в
логе панели будет `readonly database`.

## На другой сервер

Переезд на новый сервер сводится к переносу базы.

<Steps>

<Step>
### Сделайте резервную копию

Скачайте копию в **Дашборд → Бэкап и восстановление → Экспорт базы данных** (или в мобильном приложении:
**Настройки → Обновления Xray → Экспорт базы данных**) либо скопируйте
`/etc/we1ssboard/we1ssboard.db` и сертификаты. См.
[Резервное копирование и восстановление](/docs/operations/backup-restore).
</Step>

<Step>
### Установите и восстановите

Поставьте на новый сервер ту же или более новую версию We1ssBoard и восстановите
копию через **Бэкап и восстановление → Импорт базы данных**. Включите **Сохранить
настройки этой машины**, чтобы остались порты, путь и сертификаты нового сервера.
</Step>

<Step>
### Обновите адреса

Направьте домен на новый сервер или, если клиенты подключаются по IP, поменяйте
адрес в хостах и настройках подписки.
</Step>

</Steps>

## С SQLite на PostgreSQL

```bash
/usr/local/we1ssboard/we1ssboard migrate-db -dsn "postgres://user:pass@host:5432/we1ssboard?sslmode=disable"
```

Затем задайте `XUI_DB_TYPE=postgres` и `XUI_DB_DSN` в окружении службы и
перезапустите панель. См. [Переменные окружения](/docs/reference/env-vars).

## Между версиями We1ssBoard

Обновление само мигрирует базу. Перед мажорной версией прочитайте
[заметки к релизу](https://github.com/WeIbSchatten/We1ssBoard/releases) и сделайте
резервную копию. Обновление панели ставит Xray той версии, что идёт в комплекте,
если вы не закрепили другую (см. [REALITY](/docs/config/reality#совместимость-клиентов)).
